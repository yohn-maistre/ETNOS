# Serverless implementation reuse review

Checked 1 November 2026. Bounded review of primary documentation, repository READMEs/manifests and selected local source, not a full audit or an exhaustive proof that no alternatives exist. No external implementation was copied.

| Candidate | What it supplies | Fit / decision |
| --- | --- | --- |
| [Cloudflare Serverless Statusphere](https://blog.cloudflare.com/serverless-atproto), [source](https://github.com/inanna-malick/statusphere-serverless/tree/ca6e5ecd3a81dcfc80d9a9d976bac6efdad3a312) | Rust/WASM example with real AT OAuth, posting, D1/KV and DO updates plus bounded event ingestion | Useful working architectural reference. Tiny emoji-status demo, not a forum or protected-community product. Its article documents TS SDK runtime compatibility trouble; qualify our selected SDK/runtime rather than generalize this into a permanent TS limitation. Source reports MIT. Do not inherit demo KV/session, ingestion trust or broadcast assumptions without checking our threat model. |
| [Cirrus](https://github.com/ascorbic/cirrus/tree/de476f57ba1fb936c6480a8fc278b6c7fc250cab) | Single-user PDS on Workers, SQLite DO and R2; repository/federation, OAuth provider and migration | Possible separately operated test-account/PDS profile, not the Strata backend. README calls it experimental beta. `@getcirrus/pds` 0.19.0 manifest declares MIT; GitHub license metadata is null and the inspected tree lacked a standalone LICENSE file, so review actual notices before source reuse. Do not migrate important identities or assume multi-user institutional hosting is qualified. |
| [SiliconBeest](https://github.com/SJang1/siliconbeest/tree/394f8a14eebf4ab728913da67c5b17ee9a3ddebf) | Mastodon-compatible ActivityPub server using Hono/Fedify, D1/R2/KV/Queues and DO streaming | More complete serverless social-server donor/reference than a PDS. Wrong selected social protocol and not PieFed's forum/community model. Repository reports AGPL-3.0. Useful moderation, deployment and async-delivery patterns to inspect later, not a reason to maintain two federation stacks now. README claims are not independent security evidence. |
| [Fedify](https://fedify.dev/), [deployment](https://fedify.dev/manual/deploy) | ActivityPub signatures, discovery, inbox/outbox, delivery and runtime adapters including Workers | Strong candidate if an explicit public ActivityPub adapter is required. It does not implement AT or provide a whole forum. Not installed in Strata. |
| [ATcute](https://github.com/mary-ext/atcute/tree/6b378b4470a79c725ccbc1d55fd9b27cffebac89) | Modular JS/TS protocol, identity, OAuth and utility packages | Credible bounded replacement candidate if the official package blocks Workers compatibility or bundle size. Repository declares 0BSD. Inspect actual selected packages and conformance before substitution; do not add a second OAuth implementation casually. |
| [davidwkeith/workers](https://github.com/davidwkeith/workers/tree/43e7a0fb5be13fb661565a04d652f068ee5de22f) | Composable Workers packages including per-account PDS, WebAuthn, Solid and IndieWeb handlers | Useful comparison for isolation/composition. This review did not qualify its protocol parity, maturity, license files or security; no dependency selected. |
| [Tiles](https://github.com/tilesprivacy/tiles/tree/fae4dcf63021697fe9caf3b7f94f35a2fefb0a9d) | AT/Iroh sharing design previously inspected | Reference for peer artifacts and chosen disclosure. A sharelink/snapshot is not institutional authorization, a forum backend or a production private-group security proof. |
| [PieFed](https://codeberg.org/rimu/pyfedi/src/commit/36dbeb44e1a729466917dc6d141bc965f6557cb4) | Full discussion product and mature behavior vocabulary; Flask/Postgres/Redis/Celery deployment | Primary feature checklist, not a mechanical serverless port. Strata's protocol and private-source boundary differ. Preserve attribution if implementation is later reused; no donor implementation copied in this slice. |

No complete, qualified, serverless AT-based PieFed replacement was established by this review. The missing product layer remains substantial: accounts, governance, moderation, forum behavior, media, operations and a real UI. Use existing protocol implementations beneath it rather than treating a starter as a finished forum.

The selected port keeps policy in one domain engine, with local SQLite and DO SQLite adapters and one Fetch handler. Official SDK publishing is in a separate module, so offline/community API bundles do not load the whole Bluesky API client. OAuth remains a distinct qualification gate. See the feature ledger for actual delivery.

Primary runtime references: [DO SQL and transactions](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [DO rules](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/), [Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/). DO does not accept SQL BEGIN/COMMIT or PRAGMA user_version; the port uses transactionSync and a version table.
