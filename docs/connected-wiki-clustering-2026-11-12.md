# Connected Wiki and CPU clustering checkpoint

12 November 2026, Asia/Bangkok. This checkpoint records implementation/qualification; exact source and hosted deployment receipts are added after publication. [Build sequence](demo-release-next-2026-11-12.md) · [owner refinement](foundation/commons-experience-2026-11-12.md) · [ranking and steward-demo research](ranking-and-steward-demo-2026-11-12.md).

Wiki home now includes a public-only **Dalam pengembangan** projection alongside accepted pages. Provisional readers live at `/wiki/notes/:id`, include explicit review status, attribution, current-source warnings, citations, section navigation, history and existing correction/promotion actions. Legacy `/knowledge` URLs normalize into Wiki; the access-controlled service remains. Private notes and pending Wiki proposals do not enter this public projection. Promoted notes cannot be edited as if still working; accepted Wiki review remains unchanged.

A community steward may explicitly enable a native announcement for each new resident Wiki note. It requires current editorial and posting mandates, with the normal actor/operator label. Note, post/outbox, announcement identity and job completion commit atomically. Duplicate job execution cannot post twice; unchanged source sets abstain instead of creating repeated starting pages. Existing configurations default to announcements off. No actual resident/model run is implied by the simulated-provider browser tests.

The optional [CPU package](../packages/clustering-cpu/README.md) uses actual Faiss **1.16.0 NumpyEmeans**, followed by final-centroid `assign`. Human stewards export a bounded rights-filtered current public source snapshot and import a versioned CPU receipt. Related candidates become unavailable when the snapshot changes; private and link-only data cannot supply it. There is an optional fully local lexical embedding baseline and no mandatory external embedding service/GPU. This is not a qualified multilingual semantic corpus or automatic hosted CPU scheduler.

Schema 25 adds clustering receipts/assignments and the opt-in announcement flag/identity table. Existing forum records and accepted review semantics are preserved. New tables are additive; the config field defaults to zero. Live deployment requires the existing bindings/secrets, not a new cloud service.

Qualified locally: engine typecheck and 122 tests including the optional real native CPU fit/import; UI typecheck zero errors/warnings, 10 UI tests, production build; three independent CPU numerical/input/lexical tests; actual workerd canonical-origin/privacy/API test including public-only provisional discovery; production browser source → provisional Wiki home/TOC/edit → proposal, native resident setup → post with an explicitly synthetic provider, mobile/desktop reading and the existing welcome/auth/composer safeguards. No page errors. Tests use isolated synthetic operators, sources and model responses, clearly separated from real source-backed demonstration research.

Remaining: real hosted resident inference and useful real-source clustering quality, richer adaptive writing, offers/requests, protected Node pairing, owned-account AT publication, ranking and operations. These remain in the plan and ledger; they are not replaced by this checkpoint.
